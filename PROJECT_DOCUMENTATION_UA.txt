Документація BackEndForFinalProject

1. Призначення

Цей репозиторій містить ASP.NET Core Web API backend для соціального застосунку у стилі Threads.

Основні можливості:
- JWT-автентифікація з refresh tokens
- профілі користувачів
- пости з медіа, embed, локаціями, опитуваннями, лайками, репостами та переглядами
- коментарі
- підписки
- завантаження медіа в S3
- пошук GIF через Giphy
- пошук локацій через Geoapify
- відновлення пароля та підтвердження зміни пароля через Resend


2. Структура Solution

- Threads.Api
  HTTP-вхід, контролери, request-моделі, dependency injection

- Threads.Application
  DTO, інтерфейси, сервіси, бізнес-логіка, AutoMapper profiles

- Threads.Domain
  Базові сутності та спільні класи

- Threads.Infrastracture
  EF Core, репозиторії, зовнішні сервіси, security/configuration


3. Flow Запиту

1. HTTP-запит потрапляє в контролер у Threads.Api
2. Контролер перевіряє route/auth context
3. Контролер викликає application service
4. Сервіс використовує репозиторії та інтеграції
5. Сервіс повертає DTO або бізнес-результат
6. Контролер мапить результат у HTTP status code + JSON response


4. Основні Технології

- ASP.NET Core Web API
- Entity Framework Core + Npgsql
- PostgreSQL
- AWS S3
- ffmpeg / ffprobe
- Resend
- Giphy API
- Geoapify API
- Docker + Nginx


5. Основні Доменні Сутності

User
- дані акаунта і профілю
- avatar і banner
- password hash
- стан password reset code
- pending password hash для підтвердженої зміни пароля

Post
- контент
- локація
- embed
- медіа
- poll
- лічильники: likes, comments, reposts, views

Comment
- належить посту
- може мати parent comment

Like
- зв’язок user -> post

Repost
- зв’язок user -> post

Follow
- зв’язок follower -> following

Media
- метадані завантаженого image/video

Poll / PollOption / PollVote
- підтримка опитувань у постах

RefreshToken
- збережений refresh token з revoke-станом

PostView
- унікальний облік переглядів постів

7. Поведінка Media Processing

Зображення:
- валідуються
- з них витягуються метадані
- заливаються як є

Відео:
- приймаються як uploaded file
- перед завантаженням у S3 стискаються через ffmpeg у MP4
- метадані витягуються вже зі стисненого файла
- thumbnail генерується вже зі стисненого файла
- у response використовуються size/content type стисненого файла

Поточний upload limit:
- request body limit: 100 MB в ASP.NET
- Nginx також має дозволяти щонайменше 100 MB

10. Важливі Поведінкові Нюанси

- Nginx має дозволяти великі upload, інакше media upload може падати з 413 навіть якщо ASP.NET дозволяє 100 MB.
- Репости використовують окрему Reposts relation плюс денормалізований лічильник Post.RepostsCount.
- Відео тепер стискаються перед upload і зберігаються як MP4.
- Search routes живуть під /api/search/*, а не під /api/gifs чи /api/locations напряму.
- Route для media upload: /api/media/upload.

12. Примітки по Деплою

- Docker container слухає порт 8080
- docker-compose проброшує 127.0.0.1:7000 на container port 8080
- Nginx проксіює зовнішній трафік на 127.0.0.1:7000
- Якщо ти оновлюєш deploy/nginx/threads.conf у репозиторії, активний nginx config на сервері теж треба синхронізувати окремо
