Документація BackEndForFinalProject

1. Огляд

Цей репозиторій містить багатошаровий ASP.NET Core Web API backend для соціальної платформи у стилі Threads.
API підтримує:
- автентифікацію через JWT і refresh tokens
- профілі користувачів та оновлення профілю
- пости з медіа, embed, локаціями, опитуваннями, лайками, репостами та переглядами
- коментарі
- підписки між користувачами
- пошук GIF через Giphy
- пошук локацій через Geoapify
- завантаження та обробку медіа

Solution поділено на 4 проєкти:
- Threads.Api: HTTP-вхід, контролери, request-моделі, реєстрація DI
- Threads.Application: DTO, інтерфейси, сервіси, mapping profiles, бізнес-логіка
- Threads.Domain: основні сутності та спільні базові класи
- Threads.Infrastracture: EF Core, репозиторії, зовнішні інтеграції, конфігурація auth/security


2. Архітектура

Проєкт використовує класичну багатошарову структуру:
- контролери в Threads.Api обробляють HTTP-рівень
- сервіси в Threads.Application містять бізнес-логіку
- репозиторії в Threads.Infrastracture працюють з persistence через EF Core
- сутності в Threads.Domain описують модель даних

Runtime flow:
1. Запит потрапляє в контролер
2. Контролер, якщо потрібно, дістає поточного користувача з JWT
3. Контролер викликає application service
4. Сервіс використовує репозиторії та зовнішні сервіси
5. DTO-відповідь повертається в контролер
6. Контролер мапить бізнес-результат у HTTP status code і payload

Persistence:
- PostgreSQL через Entity Framework Core та Npgsql
- DbContext: Threads.Infrastracture/Data/ThreadsDbContext.cs

Зовнішні інтеграції:
- AWS S3 для зберігання медіа та signed read URL
- ffmpeg/ffprobe для метаданих медіа та thumbnail для відео
- Resend для email-кодів відновлення пароля та зміни пароля
- Giphy API для пошуку GIF
- Geoapify API для пошуку локацій


3. Основні доменні сутності

User
- дані акаунта та профілю, password hash
- стан коду для password reset
- pending password hash для зміни пароля через підтвердження по email
- зв’язки: posts, comments, likes, reposts, follows, refresh tokens, uploaded media

Post
- контент
- опціональна локація
- опціональний embed
- лічильники: views, reposts
- зв’язки: author, media, comments, likes, reposts, poll, views

Like
- зв’язок між user і post

Repost
- зв’язок між user і post
- поточний код розрахований на унікальну пару UserId + PostId

Comment
- коментарі до поста, включно з підтримкою parent comment

Follow
- зв’язок між follower і following user

Poll / PollOption / PollVote
- модель опитування для поста

Media
- метадані завантаженого image/video/gif

RefreshToken
- збережені refresh tokens з підтримкою revoke/expire

PostView
- унікальний облік переглядів по viewer/post

Усі контролери доступні під:
- /api/auth
- /api/users
- /api/posts
- /api/comments
- /api/media
- /api/search
- /api/follows


5. API Endpoints

5.1 Auth

Базовий маршрут: /api/auth

POST /register
- реєстрація користувача

POST /login
- вхід по email або username

POST /refresh
- обмін refresh token на нову пару токенів

POST /logout
- revoke refresh token

POST /forgot-password
- надсилання reset-коду на email через Resend

POST /verify-reset-code
- перевірка password reset code

POST /reset-password
- скидання пароля через email + code

POST /change-password
- authenticated 2-step flow зміни пароля
- перший виклик: currentPassword + newPassword
- другий виклик: currentPassword + code

GET /me
- профіль поточного автентифікованого користувача


5.2 Users

Базовий маршрут: /api/users

GET /
- список користувачів

GET /{id}
- користувач по Guid

GET /{username}
- користувач по username

GET /by-username/{username}
- явний варіант маршруту по username

GET /{id}/posts
- пости автора по id

GET /{username}/likes
- пости, які лайкнув користувач

GET /{username}/reposts
- пости, які репостнув користувач

PUT /me
- authenticated multipart/form-data оновлення профілю
- підтримує avatar і banner upload

DELETE /me
- authenticated self-delete


5.3 Posts

Базовий маршрут: /api/posts

GET /
- усі пости

GET /feed
- випадкова вибірка для стрічки

GET /liked
- authenticated список постів, лайкнутих поточним користувачем

GET /user/{username}
- пости по username

GET /reposted
- authenticated список постів, репостнутих поточним користувачем

GET /{id}
- пост по id

POST /{id}/view
- authenticated реєстрація унікального перегляду

POST /{id}/like
- лайк поста

DELETE /{id}/like
- зняття лайка

POST /{id}/repost
- репост поста
- повертає 409, якщо пост уже репостнули

DELETE /{id}/repost
- зняти репост
- повертає 404, якщо репоста не існує

POST /{id}/poll/vote
- голосування в опитуванні

POST /
- створення поста

PUT /{id}
- оновлення власного поста

DELETE /{id}
- видалення власного поста


5.4 Comments

Базовий маршрут: /api/comments

GET /post/{postId}
- коментарі до поста

POST /
- створення коментаря

PUT /{id}
- оновлення власного коментаря

DELETE /{id}
- видалення власного коментаря


5.5 Follows

Базовий маршрут: /api/follows

POST /{userId}
- підписатися на користувача

DELETE /{userId}
- відписатися від користувача

GET /{userId}/followers
- список followers

GET /{userId}/following
- список following

DELETE /{userId}/followers/{followId}
- видалити follower зі свого списку followers


5.6 Media

Базовий маршрут: /api/media

GET /{id}
- отримати media read URL

POST /upload
- authenticated multipart upload
- max request size налаштований на 100 MB


5.7 Search

Базовий маршрут: /api/search

GET /users?q=...
- пошук користувачів

GET /posts?q=...
- пошук постів

GET /gifs?q=...
- пошук GIF через Giphy

GET /locations?q=...
- пошук локацій через Geoapify


6. Модель автентифікації

Access tokens:
- JWT bearer tokens
- генеруються JwtTokenService
- payload включає NameIdentifier, Name, Email та стандартні JWT fields

Refresh tokens:
- випадковий 32-byte token
- у базі зберігається SHA-256 hash
- старий refresh token revoke-иться під час refresh
- усі refresh tokens revoke-яться після password reset або підтвердженої зміни пароля

Обов’язкова JWT-конфігурація:
- Jwt:Issuer
- Jwt:Audience
- Jwt:Key
- Jwt:AccessTokenLifetimeMinutes, опціонально, за замовчуванням 60


7. Media Flow

Завантаження медіа проходить через:
- MediaController
- MediaService
- FfmpegMediaProcessingService
- S3ObjectStorageService

Поточна поведінка:
- завантажений файл аналізується через ffprobe
- для відео може бути згенерований thumbnail через ffmpeg
- метадані зберігаються в БД
- оригінальне медіа і опціональний thumbnail завантажуються в S3
- у відповідях повертаються signed read URLs, а не raw storage keys

Релевантна конфігурація:
- MediaProcessing:FfmpegPath
- MediaProcessing:FfprobePath
- AWS:S3:Region
- AWS:S3:BucketName
- AWS:S3:ReadUrlExpirationMinutes


8. Email та відновлення пароля

Листи для password reset і підтвердження зміни пароля відправляються через Resend.

Обов’язкова конфігурація:
- RESEND_APITOKEN
- RESEND_FROM_EMAIL
- RESEND_FROM_NAME, опціонально

Поточний lifetime для reset/change code:
- 15 хвилин


9. Пошукові провайдери

Пошук GIF:
- Giphy

Пошук локацій:
- Geoapify
- обов’язкова конфігурація: GEOAPIFY_API_KEY

12. Dependency Injection

Усі репозиторії та сервіси зареєстровані в Threads.Api/Program.cs.

Ключові реєстрації:
- репозиторії для users, posts, comments, follows, likes, reposts, polls, refresh tokens, media
- сервіси для auth, users, posts, comments, follows, likes, reposts, polls, media
- HttpClient registrations для Giphy та Geoapify
- інтеграція Resend


13. Деплой

Контейнер:
- Dockerfile збирає і публікує Threads.Api
- runtime image встановлює ffmpeg
- застосунок слухає порт 8080 всередині контейнера

docker-compose:
- проброшено 127.0.0.1:7000 на container 8080
- читає environment з .env
- встановлює ASPNETCORE_ENVIRONMENT=Production

Інструкції для деплою через Nginx:
- дивись deploy/README.md


14. Чекліст локального запуску

Мінімальні вимоги:
- .NET SDK 10
- PostgreSQL
- ffmpeg і ffprobe доступні в системі, якщо не задані кастомні шляхи
- валідні AWS credentials/environment для доступу до S3
- валідний Resend API token, якщо використовується mail flow для відновлення/зміни пароля
- Giphy і Geoapify API keys, якщо використовуються відповідні search endpoints

Типові кроки налаштування:
1. налаштувати ConnectionStrings:DefaultConnection
2. налаштувати секцію Jwt
3. налаштувати AWS S3 values
4. налаштувати Resend values
5. налаштувати Giphy і Geoapify keys за потреби
6. застосувати міграції
7. запустити API


15. Відомі примітки по реалізації

- PostsController зараз підтримує додавання і зняття репоста на одному route через POST і DELETE.
- Вибірка reposted-постів тепер дедуплікує PostId перед побудовою порядку, що захищає читання до накочення унікального DB constraint.
- RepostsCount зберігається в Post як денормалізований лічильник, тому схема і сервісна логіка мають залишатися консистентними з relation Reposts.
- Є обидва маршрути: /api/users/{username} і /api/users/by-username/{username}.
- Search endpoints живуть під /api/search/*, а не під /api/gifs чи /api/locations напряму.
- Endpoint для media upload: /api/media/upload, а не /api/media.
