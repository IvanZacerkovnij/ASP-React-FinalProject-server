BackEndForFinalProject Documentation

1. Purpose

This repository contains an ASP.NET Core Web API backend for a Threads-like social app.

Main features:
- JWT authentication with refresh tokens
- user profiles
- posts with media, embeds, locations, polls, likes, reposts, and views
- comments
- follows
- media upload to S3
- GIF search via Giphy
- location search via Geoapify
- password reset and password change confirmation via Resend


2. Solution Structure

- Threads.Api
  HTTP entrypoint, controllers, request models, dependency injection

- Threads.Application
  DTOs, interfaces, services, business logic, AutoMapper profiles

- Threads.Domain
  Core entities and base classes

- Threads.Infrastracture
  EF Core, repositories, external services, security/configuration


3. Request Flow

1. HTTP request reaches controller in Threads.Api
2. Controller validates route/authentication context
3. Controller calls application service
4. Service uses repositories and integrations
5. Service returns DTO or business result
6. Controller maps the result to HTTP status code + JSON response


4. Main Technologies

- ASP.NET Core Web API
- Entity Framework Core + Npgsql
- PostgreSQL
- AWS S3
- ffmpeg / ffprobe
- Resend
- Giphy API
- Geoapify API
- Docker + Nginx


5. Main Domain Entities

User
- account and profile data
- avatar and banner
- password hash
- password reset code state
- pending password hash for confirmed password changes

Post
- content
- location
- embed
- media
- poll
- counters: likes, comments, reposts, views

Comment
- belongs to a post
- can have a parent comment

Like
- user to post relation

Repost
- user to post relation

Follow
- follower to following relation

Media
- uploaded image/video metadata

Poll / PollOption / PollVote
- poll support for posts

RefreshToken
- persistent refresh token with revoke state

PostView
- unique post view tracking

7. Media Processing Behavior

Images:
- validated
- metadata extracted
- uploaded as-is

Videos:
- accepted as uploaded file
- compressed with ffmpeg to MP4 before S3 upload
- metadata extracted from the compressed file
- thumbnail generated from the compressed file
- stored response uses compressed file size/content type

Current upload limit:
- request body limit: 100 MB in ASP.NET
- Nginx must also allow at least 100 MB

10. Important Behavioral Notes

- Nginx must allow large uploads, otherwise media upload can fail with 413 even if ASP.NET allows 100 MB.
- Reposts use a dedicated Reposts relation plus a denormalized Post.RepostsCount counter.
- Videos are now compressed before upload and stored as MP4.
- Search routes are under /api/search/*, not /api/gifs or /api/locations directly.
- Media upload route is /api/media/upload.


11. Local Run Checklist

1. Configure database connection string
2. Configure JWT settings
3. Configure AWS S3 settings
4. Configure Resend
5. Configure Giphy and Geoapify if needed
6. Apply EF migrations
7. Run the API


12. Deployment Notes

- Docker container listens on port 8080
- docker-compose binds 127.0.0.1:7000 to container port 8080
- Nginx proxies public traffic to 127.0.0.1:7000
- If you update deploy/nginx/threads.conf in the repository, the server-side active nginx config must also be synchronized
